**WordPress (Royal MCP "Suzu Travels WordPress" cloud connector) traps:**
- The hub 10080 must keep `_wp_page_template` = `page.php`. Never set it to "default" (the theme's `page-cabs.php` would take over by slug and bury the new design).
- `wp_create_page` has no slug field: create the page with a title whose words equal the slug (e.g. "Delhi to Haridwar Taxi" → `delhi-to-haridwar-taxi`), parent 10080, then confirm/set with `wp_update_seo_meta` `slug`.
- Page content must be the ONE-line `out/<slug>.min.html` from `build.py` (wpautop breaks multi-line HTML). After any content write, read the page back (`wp_get_page`) and confirm the stored content length equals the file's byte length; if not, fix before moving on.
- WP Rocket full-page cache: verify live twice — `?v=<random>` and plain — both 200, one H1, `<meta name="robots"` contains `index`, right title. A post-meta-only change does not purge the cache: re-save the page (same title via `wp_update_page`) to purge. If plain still shows old content after that, report "WP Rocket Clear & Preload needed".
- WP Rocket "Delay JS" means the kit's calculator/forms run after the first user interaction — test them after a mouse move/scroll. The console errors `moment is not defined`, `setSettings`, `feather is not defined` are pre-existing site-wide — ignore them.
- Hostinger bot protection may show a reCAPTCHA to headless Chromium after many requests — keep headless checks to a few page loads; use curl for the rest.
- Every Royal MCP write returns a 72-hour undo token — put it in `LOG.md`.
- Never delete content, never change existing URLs/slugs, no PHP/theme/plugin/.htaccess/menu/settings edits, never touch the static homepage.
